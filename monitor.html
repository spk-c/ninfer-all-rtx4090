NInfer Monitor

See local inference and GPU activity in your browser. The read-only dashboard is bundled with ninfer-serve, including the portable Windows release, without a separate Python process, external assets or cloud service.

What you can monitor

Live token throughput

Decode and computed prefill rates from server token counters, sampled every three seconds. Separate time series make workload changes visible.

NVIDIA GPU telemetry

Utilization, VRAM, temperature and power via optional NVML. Select the NVML GPU index from 0 to 7. Missing sensor readings show a dash.

DFlash2 acceptance

Aggregated accepted/drafted model tokens from DFlash2 events among the last 50 requests. N-gram proposals are excluded.

KV cache and requests

Device KV occupancy, configured context limit, active/waiting requests and admitted requests. KV occupancy is not the total chat context length.

Recent request events

Up to 50 completed, rejected or failed requests: timestamp, status, token counts, cached tokens, decode speed and duration. No prompts or completions in this feed.

Server activity

Completed and failed request counts, reused prompt tokens, uptime and aggregate samples. The browser keeps up to 120 samples in tab memory and pauses polling when hidden.

Open the built-in dashboard

Start ninfer-serve with a compatible native model. Open the following address in the browser on the machine running the server:

http://127.0.0.1:8080/monitor

Replace 8080 with your configured port. For example, with --port 8099 use:

http://127.0.0.1:8099/monitor

If API-key authentication is enabled, enter the key in the dashboard password field. In router mode enter the exact model ID to inspect a model. Select the appropriate NVML GPU index. The monitor polls its own origin; this public project website never connects to your local server.

Windows setup · Launch planner

Responsive browser view

The layout adapts to narrow screens, stacking metric cards and charts. Open the panel on a browser that can reach your NInfer server; local-only binding is the default recommendation for safety.

Privacy and authentication

The monitor HTML contains no embedded server data. API keys stay in tab memory, not localStorage, cookies or URL parameters. Stats, metrics, GPU and recent-request endpoints retain the server's API authentication. Use localhost unless remote access is intentionally secured.

Measurement limits

Throughput is a server-wide counter difference over the last polling interval, not per-request latency or a standardized benchmark. Rates are blank on the first sample. Optional sensors may be unavailable; history resets when the server restarts.

Metrics API and advanced logging

EndpointPurpose
GET /monitorBuilt-in HTML dashboard
GET /statsServer statistics in JSON
GET /metricsPrometheus-compatible metrics
GET /monitor/gpu?index=0Optional NVML sensor readings
GET /monitor/requestsBounded recent request metadata

For longer history, CPU/RAM sensors and full per-request JSONL logging, see the optional Python monitor sidecar. The built-in webpanel does not require it.
